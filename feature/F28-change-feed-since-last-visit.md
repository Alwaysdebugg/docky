# F28 · 变更动态(自上次以来)

> 一句话:每次进入 docky,主动告诉你"自上次来过之后,库里**新增/改动/删除了哪些文档**",一眼掌握变化,而不是被动地不知道发生了什么。

## 背景与痛点

库在被多方(人 + 多个 agent)持续改写,但**用户对"发生了什么"毫无感知**:

- F04 记录**我打开过什么**(个人 recency),F08 提供**单篇的 history**,F22 是**agent 待审队列**——但都不是"整库自我上次以来的变化总览"。
- 在 agent 频繁写入(F07/F20)的场景下,人回到库里**完全不知道这期间多了/改了什么**,容易错过关键更新或重复劳动。

## 目标 / 非目标

**目标**
- 记录**每项目的"上次到访时间"**(复用 F04 的状态文件)。
- 进入时给出**变更动态**:自上次以来的 新增 / 编辑 / 删除 文档清单(来源:F08 提交;F08 未上线时退回**文件 mtime** 对比)。
- TUI 主页"🆕 自上次以来"区块 + `docky whatsnew`;Enter 打开或看 diff(F08)。
- **标记已读**(更新到访时间);可 `--since <时间>` 自定义窗口。

**非目标**
- 不做实时推送/通知(进入时拉取即可)。
- 不替代 F22 的 agent 审阅(F28 是"知情",F22 是"处置")。

## 用户故事

- 作为开发者,我早上进 docky,看到"自昨天:新增 3 篇排查、改了 1 份设计",点进去快速过一遍。
- 作为团队成员,我 `docky whatsnew --since 7d` 回顾本周库内动态。

## 交互设计

```
🆕 自上次以来(2 天前 → 现在)
  + design/限流设计.md        新增 · agent
  ~ design/鉴权改造.md        编辑 · (看 diff)
  - debug/废弃排查.md         删除
↑/↓ 选择 · Enter 打开/Diff · m 标为已读 · Esc
```

## 技术落点

- `src/changes.ts`:对比"上次到访"与当前(优先 F08 `git log --since`;回退扫描 `mtime`/列表快照);分类 add/edit/remove。
- 状态:`.docky-state.json`(F04)增 `lastSeen`;进入即读、`m`/退出即更新。
- TUI 主页区块 + `docky whatsnew`;diff 复用 F08。

## 验收标准

- [ ] 进入时展示自上次以来的 新增/编辑/删除清单。
- [ ] 有 F08 时基于提交,无 F08 时基于 mtime 回退,均可用。
- [ ] Enter 打开或查看 diff;标为已读后清单清空并更新到访时间。
- [ ] `docky whatsnew [--since]` 可用;作用域隔离不变;`changes` 有单测。

## 衡量指标

- 用户进入后点击变更项的比例(知情转化)。
- 因"没注意到更新"导致的重复/冲突减少。

## 风险与依赖

- mtime 回退不如提交精确(无法识别"删除");以 F08 为佳、mtime 为兜底并标注精度。
- 复用 F04(lastSeen)、F08(log/diff)、F21(主页区块)。

## 与其他提案的关系(迭代递进)

- 把 **F08 的留痕** 与 **F04 的到访** 组合成"主动知情"层;与 **F22** 分工(知情 vs 处置)。
- 是 **F21 仪表盘** 的"动态"补充(F21 看现状,F28 看增量)。
