# F38 · 命令与快捷键可发现性

> 一句话:一个全局 `?` 浮层,按当前界面**列出可用快捷键与命令**(并允许自定义键位),让 8 轮迭代攒下的一大堆操作可被发现、可被记住。

## 背景与痛点

功能越加越多,**操作却越来越难发现**:

- 快捷键散落在各模式、只靠**底部一行临时提示**:browse 的 `↑↓/Enter/e/q`、results、quickopen 的 `Ctrl-P`、import 三筛的 `Space/t/s/p/m/a`、F04 的 `R` 自愈、F08 的 `h` 历史……
- `/help` 只列**命令**(`COMMANDS`,`src/commands.ts`),**不含快捷键**;没有"当前界面能按什么"的总览,也**无法改键**。
- 结果:新功能"藏得很深",用户记不住、用不上,等于白做。

## 目标 / 非目标

**目标**
- **全局 `?`**:在任意模式弹出**上下文相关**的快捷键 + 可用命令浮层(含一句话说明)。
- **可搜索速查表**:`docky keys` / `/keys` 列出全部键位与命令。
- **自定义键位**:经 F18 配置改键(冲突检测)。
- 单一**键位注册表**作为真相源,同时驱动浮层与实际 `useInput` 处理。

**非目标**
- 不改默认键位(只新增发现/自定义能力)。
- 不做宏录制(自定义命令链可留后续)。

## 用户故事

- 作为用户,任何界面按 `?` 就知道"这儿能按什么",不必猜。
- 作为习惯 vim 的人,我把浏览键改成 `j/k`。

## 交互设计

```
? 快捷键(当前:文档浏览器)
  ↑/↓   选择            Enter  预览
  e     编辑器打开       h      历史(F08)
  /     命令菜单         ?      关闭本浮层
全局:Ctrl-P 快速打开 · Esc 返回 · :keys 全部
```

## 技术落点

- 新增 `src/keymap.ts`:每个 mode 的 `{key, label, action}` 注册表(单一真相源);`tui.tsx` 的 `useInput` 与 `?` 浮层都读它。
- `?` 浮层组件(复用现有选择列表渲染);`/keys`、`docky keys`。
- 自定义键位:F18 配置覆盖默认,启动时校验冲突。

## 验收标准

- [ ] 任意模式按 `?` 显示该模式的快捷键 + 可用命令。
- [ ] `docky keys` / `/keys` 列出完整速查表。
- [ ] 可经 F18 自定义键位并检测冲突。
- [ ] 键位注册表是唯一真相源(浮层与实际处理一致,不漂移)。
- [ ] 浮层与 keymap 有单测。

## 衡量指标

- 较少使用的快捷键(如 import 三筛、F08 历史)的使用率上升。
- 新用户发现高级功能的时间下降。

## 风险与依赖

- 把现有散落键位收敛进注册表时,需保证零回退(先补测试)。
- 自定义键位依赖 F18;`?` 不得与各模式既有键冲突。

## 与其他提案的关系(迭代递进)

- **让 R1–R7 攒下的所有键位/命令变得可发现**:是这套日益丰富的 TUI 的"说明书层"。
- 自定义键位复用 **F18**;与 **F39**(无障碍)同属"让更多人用得了"的内功。
