# F02 · 模糊快速打开 / 命令面板

> 一句话:输入几个字符就能在当前作用域内**模糊定位任意文档并打开**,免去记忆精确相对路径或层层浏览。

## 背景与痛点

当前"打开一篇文档"成本偏高:

- `/open <相对路径>` 要求**精确相对路径**(`src/commands.ts`),用户得先知道 `design/架构.md` 这种完整路径。
- `/list` 虽是交互式层级浏览(`src/tui.tsx` `enterBrowse`),但**没有增量过滤**——文档一多就得用 ↑/↓ 一路滚。
- 没有一个"我只记得名字里有 `登录`"就能秒到的入口。对高频动作(找回某篇文档)而言,这是最大的日常摩擦。

## 目标 / 非目标

**目标**
- 提供 fzf 风格的**模糊快速打开**:`/o`(或 `Ctrl-P`)拉起浮层,输入即增量过滤,匹配 `name + title + type`,↑/↓ 选中,Enter 在分页器打开。
- 空查询时默认呈现 **最近访问/置顶**(对接 F04),让"再打开上一篇"成为一键。
- 子序列模糊匹配 + 简单排序(前缀/连续匹配加权;最近访问加权)。

**非目标**
- 不替代 `/list` 的层级浏览(二者并存:浏览用于"逛",快速打开用于"直奔")。
- 不做全文模糊(全文检索归 F01/`search`);本提案匹配的是**文档名/标题/类型**。

## 用户故事

- 作为开发者,我只记得"那篇讲登录的设计稿",输入 `denglu`/`登录` 就能在候选里看到并回车打开。
- 作为重度用户,我按 `Ctrl-P` 直接回车,打开的就是我**上一篇**在看的文档。

## 交互设计

```
quick open ›  登录
  ▸ design/  登录鉴权改造        (登录鉴权.md)
    debug/   登录丢 session 排查 (登录排查.md)
    prompts/ 登录话术            (login-prompt.md)
↑/↓ 选择 · Enter 打开 · Esc 取消        最近 3 · 置顶 1
```

- 触发:命令菜单加 `/o`(usage `/o [关键词]`),或全局 `Ctrl-P`(在 `useInput` 中拦截)。
- 候选来源:`core.listDocs(vault, project)`(作用域内全量,N 通常很小,客户端匹配即可)。
- 匹配:大小写不敏感的子序列匹配,命中片段加亮;排序 = 匹配质量 +(F04)最近权重。

## 技术落点

- `src/tui.tsx`:新增 `mode === "quickopen"`,带一个输入框(可复用 `ink-text-input`)+ 候选列表(复用 F01 抽出的可选中列表组件)。
- `src/commands.ts`:注册 `/o` 到 `COMMANDS` 与建议菜单;TUI 特判进入 quickopen。
- 新增 `src/match.ts`:纯函数 `fuzzy(query, items)`,便于单测。
- 数据来自既有 `core.listDocs`,无需改 core。

## 验收标准

- [x] `/o` 或 `Ctrl-P` 拉起快速打开浮层。
- [x] 输入即增量过滤,匹配 `name/title/type` 且大小写不敏感、支持子序列。
- [x] Enter 在同终端分页器打开选中文档;Esc 取消返回。
- [x] 空查询时显示最近/置顶(若 F04 已上线)或全部按类型排列。
- [x] `src/match.ts` 的模糊匹配有独立单测(含中英文、子序列、排序)。
- [x] 越界/跨项目文档不会出现在候选中。

## 衡量指标

- "想打开某文档 → 真正打开"的平均耗时/按键数显著下降。
- `/o` 使用频次占所有 open 来源的比例(目标成为主力入口)。

## 风险与依赖

- 中文模糊匹配需考虑无分词的子序列匹配与拼音(拼音可放后续);首版先做字面子序列。
- `Ctrl-P` 与终端/Ink 既有按键无冲突(需在 `useInput` 中验证)。
- 复用 F01 的可选中列表组件;建议 F01 先落地公共组件。

## 与其他提案的关系

- 复用 **F01** 抽出的可选中列表组件与分页器打开能力。
- 以 **F04(最近/置顶)** 作为空查询时的默认候选与排序权重来源。
- 受益于 **F03(标签)**:未来可 `/o #tag` 在标签内快速打开。
