# F27 · 本地 Web 浏览与检索界面(docky serve)

> 一句话:`docky serve` 起一个本地只读网页界面,在浏览器里**浏览 / 检索 / 阅读**整库(含真实渲染、关系图、反链),给偏好浏览器或不用终端的人一个入口。

## 背景与痛点

docky 的消费面只有三个,**唯独缺了浏览器**:

- 入口 = CLI、TUI、MCP(给 agent),或直接看 raw md(README)。
- F17 能**导出静态文件**(send-out),但那是"快照寄出去",不是**实时可交互**地浏览这个不断变化的库。
- 长设计稿在终端读体验有限(Mermaid/表格/图片);团队里 QA/PM/新人往往更想在浏览器里读、点链接、搜一下。

## 目标 / 非目标

**目标**
- `docky serve [-p 项目] [--port N]`:启本地 HTTP 服务(用 **Node 内置 `http`,不引新依赖**),提供只读 Web:
  - 按类型浏览、单篇**完整渲染**(marked → HTML,真渲染表格/代码/Mermaid);
  - **检索**(F13 / F26 混合);**关系图**(F23);**反向链接**(F12);**状态/标签徽标**(F03)。
- **默认只读 + 仅绑定 `127.0.0.1`**(安全);作用域内(或 F15 授权)文档可见。

**非目标**
- 不做线上托管/鉴权(本地自用;远程交给用户自行代理)。
- 首版不在 Web 端做编辑(只读浏览;编辑仍走编辑器/TUI)。

## 用户故事

- 作为 PM,我 `docky serve` 后在浏览器里读设计稿、点 `[[链接]]` 跳转、搜关键词,不用学终端。
- 作为开发者,我把含 Mermaid 的架构图在浏览器里看到真实渲染。

## 交互设计

```
$ docky serve -p my-app
▸ docky web 已启动:http://127.0.0.1:4040  (只读 · 按 Ctrl-C 停止)
  /            项目首页(INDEX + 概览/F21)
  /doc/...     单篇渲染(反链/大纲/F12·F16)
  /search?q=   混合检索(F13/F26)
  /graph       关系图谱(F23)
```

## 技术落点

- `src/serve.ts`:`node:http` 服务;路由 `/`、`/doc/:rel`、`/search`、`/graph`;HTML 由 `marked` 渲染(已是依赖),内联 CSS/JS,无新依赖。
- 复用:`core.listDocs/readDoc`+`safePath`(scope)、F13/F26(检索)、F12(反链)、F23(图)、F16(渲染/大纲逻辑共享)。
- 安全:默认 `127.0.0.1`、只读;写操作端点不存在。

## 验收标准

- [ ] `docky serve` 启动本地只读 Web,默认绑定 127.0.0.1。
- [ ] 可浏览/渲染单篇(表格/代码/Mermaid),点 `[[链接]]` 站内跳转。
- [ ] Web 检索走 F13/F26;含关系图(F23)与反链(F12)。
- [ ] 仅作用域内(或 F15 授权)文档可访问;越界 404。
- [ ] 不引入新运行时依赖;`serve` 路由有测试。

## 衡量指标

- 非终端用户(PM/QA)通过 Web 阅读的会话数。
- 因"不会用终端"而拿不到文档的情况减少。

## 风险与依赖

- 安全:务必默认仅本地、只读;明确提示不要裸暴露到公网。
- 复用 F16 渲染、F13/F26 检索、F23 图、F12 反链;缺席项在 Web 端相应降级。

## 与其他提案的关系(迭代递进)

- 与 **F17 互补**:F17 导出静态快照寄出,F27 提供**实时可交互**的本地浏览。
- 复用 **F12/F13/F16/F23/F26** 作为 Web 端的内容与能力来源,是它们的"第二块屏"。
