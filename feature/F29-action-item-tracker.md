# F29 · 行动项追踪(跨文档 TODO 聚合)

> 一句话:把散落在各篇文档里的 `- [ ]` 待办**聚合成一张可勾选的行动清单**,让 docky 不只是"读文档",还能"推进事情"。

## 背景与痛点

文档里写了一堆待办,却**无法统观、无法推进**:

- `plan` 类型(`DOC_TYPES`)本质是"要做的事",design/debug 里也常有 `- [ ]` 后续项,但 docky 把文档当**不透明 blob**,正文里的待办在聚合层**完全不可见**。
- 想知道"这个项目还有哪些没做完",只能逐篇打开数 checkbox。
- 已交付的检索/列表都按"文档"维度,**没有"行动项"维度**。

## 目标 / 非目标

**目标**
- 解析全库 Markdown 任务项(`- [ ] / - [x]`,含行号与所属文档)。
- `docky todos [-p 项目] [--open|--done]` + TUI `/todos`:按文档分组的聚合清单;`--open` 只看未完成。
- **就地跳转与回写**:Enter 跳到该待办所在行(复用 F01 `pageDoc`+行号);在清单里勾选 → **回写**到原文档对应行并提交(F08)。
- 可按 F03 `#标签/--status` 过滤(如只看 active plan 的待办);未完成数接入 F21 仪表盘。

**非目标**
- 不引入独立任务系统(待办仍是文档里的 checkbox,docky 只做聚合视图)。
- 不做指派/截止日期等项目管理字段(可在行内文本自带)。

## 用户故事

- 作为开发者,我 `/todos --open` 看到本项目所有未完成项,挨个点进去处理。
- 作为负责人,我在仪表盘看到"还有 14 项未完成",点开就是聚合清单。

## 交互设计

```
行动项 · my-app  (未完成 14 · 已完成 32)
plan/灰度计划.md
  [ ] 配置灰度开关            → Enter 跳到 L23
  [ ] 监控接入
design/鉴权改造.md
  [ ] 补充失败重试设计
↑/↓ 选择 · Space 勾选(回写) · Enter 跳转 · t 过滤标签 · Esc
```

## 技术落点

- `src/todos.ts`:从 `listDocs` 内容提取 checkbox 行(状态 + 行号 + 文本),纯函数可测。
- 勾选回写:定位行 → 改 `[ ]`↔`[x]` → 保存 + F08 提交;复用 F10 覆盖语义保正文。
- TUI `/todos`:复用 F01 可选中列表 + `pageDoc` 行跳转;F03 过滤(`filterDocs`/标签)。
- `docky todos` CLI;计数供 F21。

## 验收标准

- [ ] 跨文档解析任务项,聚合为按文档分组的清单(含未完成/已完成计数)。
- [ ] Enter 跳到待办所在行;Space 勾选并**回写**原文档 + 提交(F08)。
- [ ] 支持 `--open/--done` 与 F03 标签/状态过滤。
- [ ] 回写保留正文与其他行,幂等;`src/todos.ts` 有单测。
- [ ] 作用域隔离不变;未完成数可供 F21。

## 衡量指标

- 经聚合清单完成(勾选)的行动项数。
- plan 文档中长期未完成 `- [ ]` 的存量下降。

## 风险与依赖

- 回写需精确定位行,避免误改(以行号 + 原文校验)。
- 复用 F01(跳转)、F03(过滤)、F08(提交)、F21(计数)。

## 与其他提案的关系(迭代递进)

- 在 F01/F03/F08 之上新增**"行动项"维度**,让"plan 类型"名副其实。
- 计数与清单可嵌入 **F21 仪表盘**、被 **F24 智能文件夹**(如"我的待办")复用。
