# F43 · 文档评论与标注

> 一句话:给文档加一层**不污染正文的评论/标注**(可定位到行、可归属、可解决),让人审阅、人给 agent 反馈、团队讨论都有处落,而不必硬改正文。

## 背景与痛点

有了 F22 审阅,却**没有"留句话"的地方**:

- F22(收件箱)能对 agent 产出**通过/退回/编辑/合并**,但要表达"这段过期了""@agent 补一下重试逻辑"**只能改正文**——既重又丢失意图。
- 没有评论/标注概念:frontmatter 有 status/tags/source/review(F03/F22),但**没有针对某行/某段的讨论**。
- 团队场景(F31)与"人给 agent 反馈让其改稿"都缺这一层。

## 目标 / 非目标

**目标**
- **旁挂式评论**(不写进正文):`docky comment <rel> [--line N] "文字"`;TUI 阅读时按 `c` 加批注。
- **可定位/可归属/可解决**:评论可锚到行,带作者(F31 身份),可标记 resolved;阅读视图(F16)在页侧/底部展示。
- **回流给 agent**:经 MCP(F25/F07)把未解决评论提供给 agent,实现"按评论改稿"的闭环。
- **被汇总**:F22 收件箱 / F19 巡检显示"有未解决评论"的文档。

**非目标**
- 不做实时多人光标协同(异步评论即可)。
- 评论不进文档正文(导出 F17 默认不含,除非显式带上)。

## 用户故事

- 作为审阅者,我在某行加"这里与新方案冲突",不动正文;作者/agent 看到后改。
- 作为开发者,我让 agent"处理这篇的未解决评论",它经 MCP 读到评论并改稿。

## 交互设计

```
# 阅读 design/鉴权改造.md(F16,底部)
评论(2 未解决)
  L42 @张三:这段与限流方案冲突            [r 解决]
  L88 @你:补充失败重试                    [r 解决]
c 新建 · r 解决 · Enter 跳到行
```

## 技术落点

- 旁挂存储:作用域内 `.comments/<rel>.json`(以 `.` 前缀,排除出 listDocs;`safePath` 守边界)。
- `src/comments.ts`:增删改查、按行锚定、resolved 状态、归属(F31)。
- 阅读集成(F16,行跳转复用 F01);MCP(F25/F07)暴露未解决评论;F22/F19 汇总。

## 验收标准

- [ ] 可对文档(可定位到行)增/删/解决评论,不改正文。
- [ ] 评论带作者与时间,阅读视图可见、可跳行。
- [ ] 未解决评论可经 MCP 提供给 agent;F22/F19 可汇总。
- [ ] 评论受作用域隔离;`src/comments.ts` 有单测。

## 衡量指标

- 经评论(而非直接改正文)完成的反馈比例。
- agent"按评论改稿"的闭环完成次数。

## 风险与依赖

- 行锚点会因正文变动漂移:存行号 + 锚文本,失效时降级为"文档级评论"。
- 依赖 F16(阅读展示)、F01(跳行)、F31(归属)、F22/F19(汇总)、F25/F07(回流 agent)。

## 与其他提案的关系(迭代递进)

- 在 **F22 审阅**之上加"**讨论/反馈**"层,把"通过/退回"细化为"逐点评论 → 改稿 → 解决"。
- 评论回流 agent,与 **F20/F22** 一起完善"人 ↔ agent"的文档协作闭环。
