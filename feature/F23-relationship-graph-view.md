# F23 · 关系图谱视图

> 一句话:把 F12 的互链/反链从"每篇一份列表"升级为**整库关系图谱**——看清枢纽、簇群与孤岛,并能顺着关系导航打开。

## 背景与痛点

- F12 建了 `[[..]]` 互链与反向链接,但**明确把图形化留给了后续**("不做图形化关系图,首版用列表")。
- 列表视角只能看"这一篇连了谁",**看不到全局结构**:哪些文档是枢纽(被大量引用)、哪些自成一簇、哪些是孤岛(无任何关联)。
- 对一个意在"织网"的知识库,缺了纵览这张网的视图。

## 目标 / 非目标

**目标**
- `docky graph [-p 项目]` + TUI `/graph`:以**终端可读的树/簇**呈现关系图谱:
  - **枢纽**(入链最多,F12 反链)置顶突出;
  - **簇群**(连通分量)分组;
  - **孤岛**(无出入链)单列,提示"可考虑链接或归档(F21)";
  - **断链**(F12/F19)标 ⚠。
- 可导航:选中节点 → 展开其邻居 → Enter 打开(复用 F01 `pageDoc`)。
- 可把图谱导出给 F17(站点页/Graphviz),供浏览器查看。

**非目标**
- 终端内不做力导向画布(用层级/簇的文本布局);真正的可视化交给 F17 导出。
- 不改链接语义(纯消费 F12 的索引)。

## 用户故事

- 作为开发者,我 `/graph` 看到"鉴权改造"是中心枢纽,周围挂着 4 篇排查与 1 份计划,点进去顺藤摸瓜。
- 作为维护者,我看到 7 篇孤岛文档,挨个决定链接或归档。

## 交互设计

```
my-app · 关系图谱
枢纽 ★ design/鉴权改造 (入链 11)
  ├─ debug/登录超时
  ├─ debug/会话丢失
  └─ plan/灰度计划  ─→ ⚠ [[旧规范]] 断链
簇 · 支付  (5 篇互联)
孤岛(7)  prompts/杂记 · debug/临时笔记 …
↑/↓ 选择 · → 展开 · Enter 打开 · Esc 返回
```

## 技术落点

- 新增 `src/graph.ts`:由 F12 的链接/反链索引构建邻接表;计算连通分量、入度排序、孤立节点。
- TUI `/graph`:树/簇渲染 + 节点导航(复用 F01 选择/打开)。
- 导出:把邻接表序列化为 F17 的站点关系页 / Graphviz DOT。

## 验收标准

- [x] `docky graph` / `/graph` 呈现枢纽、簇群、孤岛与断链。
- [x] 可选中节点展开邻居并 Enter 打开对应文档。
- [x] 可导出关系图谱(供 F17)。
- [x] 作用域隔离不变(仅在本项目/F15 授权域内构图);`src/graph.ts` 有单测。

## 衡量指标

- 孤岛文档占比下降(网在变密)。
- 通过图谱导航完成的跳转次数。

## 风险与依赖

- **强依赖 F12**(无链接索引则无图);F12 未上线时本特性不可用并明确提示。
- 大库布局需限制展开深度,避免刷屏。

## 与其他提案的关系(迭代递进)

- **F12 的显式后续**:把其刻意推迟的"图形化"补上(列表 → 图谱)。
- 为 **F21 仪表盘** 提供"枢纽/孤岛"洞察、为 **F17 导出** 提供关系页。
