## 二、建议落地优先级

**P0 — 现在做(收口核心,高杠杆)**
- **F20** 写覆盖保护 → 补上数据安全最后一块(F08+F10 已收口删除/覆盖,仅剩 agent 写)
- **F18** 配置入口 → 后续大量功能(主题/阈值/模型/locale)都挂在它上
- **F26** 语义检索 → 检索从"能搜到"到"按意思搜",且是 F46/F47 的前置
- **F19** 文档巡检 → 库长大后的质量底线

**P1 — 紧接着(差异化旗舰,依赖 P0)**
- **F46** Ask 问答(依赖 F26)· **F47** 记忆层 · **F22** agent 产出审阅
- 轻量补强:**F24** 智能文件夹 · **F28** 变更动态 · **F45** 安全重命名

**P2 — 视需求再做**
- **F31/F32** 团队同步 / 多 vault(等真有多人或多客户)
- **F49** 会话沉淀 · **F33** 文档↔代码 · **F16/F17** 阅读/导出

**P3 — 冻结 / 远期(当前阶段过度设计)**
- F27 Web UI · F50 SDK · F51 多 agent · F54 企业治理 · F55 多模态 · F23 图谱 · F34 通知 · F39 无障碍 · F40 i18n · F42 快照 · F36/F37/F38 部分内功

## 三、一句话建议

docky 的差异化在 **C1 检索 + C2 agent 上下文/记忆 + C11 作用域隔离 + C13 MCP 接入**——把这四块做深做透,就已经是好产品。其余多数提案是"锦上添花"或重叠切面,**该收敛进上面 4–5 个核心能力,而不是当 40 个独立功能去排期**。建议接下来按 P0→P1 推进,P3 直接冻结。
