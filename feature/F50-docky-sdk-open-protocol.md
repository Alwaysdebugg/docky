# F50 · Docky SDK 与开放协议

> 一句话:把 docky 从"一个工具"升级为"**一个平台**"——提供稳定的 SDK 与开放协议,让任何 IDE / agent 框架 / CI 都能接入 docky 的知识与记忆层,并用插件扩展检索、捕获、导出。

## 战略定位(为什么这是旗舰级跃迁)

Claude Code 靠 MCP/SDK 生态成为平台。docky 要同级,就不能只服务自己的 CLI/TUI——它得成为**任何 agent 都能依赖的标准知识/记忆底座**,让第三方在其上构建。生态飞轮一旦转起来,docky 的价值就不再受限于自身功能数,而由接入它的工具数决定。

## 背景与痛点

- 现有对外面只有:MCP 工具(F25 还想加 Resources/Prompts)、CLI(F35 想加 `--json`)。这些是**点状接口**,不是一套**稳定、版本化、可被第三方依赖的 SDK/协议**。
- 想让某个 IDE 插件、某个 agent 框架"用 docky 当记忆层",今天**没有清晰的契约与扩展点**——能力散落在 CLI 文案与内部函数里。
- F46–F49 把 docky 做成了知识/记忆平台的"内核",但**缺一层让外部接入与扩展的开放面**。

## 目标 / 非目标

**目标**
- **稳定 SDK**:把核心能力(解析作用域、检索 F13/F26、上下文 F07、问答 F46、记忆 F47/`remember`/`recall`、捕获 F49)收敛为**版本化的程序接口**(Node 库 + 语言无关的 JSON/MCP 契约)。
- **开放协议**:文档化的 `docky://` 资源协议(F25)+ 操作契约(F35 JSON)+ 记忆/召回契约,任何工具据此接入。
- **插件机制**:可插拔的 **检索器 / 捕获器 / 导出器 / 嵌入源**(F26 嵌入、F49 捕获、F17 导出、F46 模型)走统一扩展点。
- **接入示例**:至少一个参考集成(如编辑器插件或 CI 步骤)证明可用。

**非目标**
- 不做托管云服务(先开放本地 SDK/协议;云是后话)。
- 不破坏现有 CLI/TUI/MCP(SDK 是其下沉的共享内核)。

## 用户故事

- 作为插件作者,我用 docky SDK 给我的编辑器加"侧边栏知识面板",几十行接上 F48 的主动推荐。
- 作为平台团队,我把 docky 作为内部所有 agent 的标准记忆层(F47),通过协议统一接入。

## 交互设计

```ts
// Node SDK(示意)
import { Docky } from "docky";
const d = await Docky.open({ project: "my-app" });
const ans = await d.ask("为什么用 JWT?");        // F46
await d.remember({ type: "gotcha", text: "回调需幂等" }); // F47
d.use(myCustomRetriever);                          // 插件扩展点
```
```
docky://my-app/design/鉴权改造.md   (F25 资源协议)
```

## 技术落点

- `src/sdk.ts`:把 `core`/检索/上下文/问答/记忆/捕获收敛为**版本化公共 API**(语义化版本);现有 CLI/TUI/MCP 改为 SDK 的消费者(去重内核)。
- 协议文档:`docky://` 资源(F25)+ JSON 操作(F35)+ 记忆/召回契约,集中成 `PROTOCOL.md`。
- 插件接口:检索器/捕获器/导出器/嵌入源的统一注册点;一个参考集成示例。

## 验收标准

- [ ] 提供版本化 Node SDK,暴露 检索/上下文/问答/记忆/捕获 等核心能力。
- [ ] 开放协议(资源 `docky://` + JSON 操作 + 记忆契约)有文档(`PROTOCOL.md`)。
- [ ] 插件机制可注册自定义 检索器/捕获器/导出器/嵌入源。
- [ ] 至少一个参考集成跑通;现有 CLI/TUI/MCP 不回退(改为 SDK 消费者)。
- [ ] SDK 公共 API 与插件加载有单测与契约测试。

## 衡量指标

- 接入 docky 的第三方工具/集成数量(生态广度)。
- 经 SDK/协议(而非内部直调)使用 docky 的比例。

## 风险与依赖

- API 稳定性是生命线:语义化版本 + 弃用策略,避免破坏下游。
- 汇聚了几乎所有能力:F07/F13/F25/F26/F35/F46/F47/F49——宜在这些内核成型后再固化 SDK。

## 与其他提案的关系(迭代递进)

- 把 **F25(MCP)+ F35(JSON)** 的点状接口,升级为**成体系的 SDK + 开放协议 + 插件生态**。
- 是 R10 平台化的收口:F46(问)/F47(记)/F48(推)/F49(录)是内核能力,**F50 把它们开放出去**,让 docky 成为可被生态依赖的知识/记忆平台。
