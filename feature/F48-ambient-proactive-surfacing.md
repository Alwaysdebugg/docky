# F48 · 环境感知主动推荐

> 一句话:在你(或 agent)动手之前,docky 就**主动浮现**相关知识——打开 `auth.ts` 时自动带出它的设计稿、上次的 bug、关键决策。从"你去查的库"变成"始终快你一步的助手"。

## 战略定位(为什么这是旗舰级跃迁)

Claude Code 的强大在于**在上下文里主动帮你**。docky 若只是"等你来搜",永远只是工具。让它**感知当前工作环境**(在编辑哪个文件、报了什么错、在做什么任务)并**主动推送**最相关的过程文档/决策/记忆,docky 就具备了"环境智能",成为开发流里随时在场的知识层。

## 背景与痛点

- 现有能力都是**被动**的:F01/F13/F26 要你来搜,F07 要 agent 来拉,F28 只在你进 docky 时看变更。
- 真正高价值的时刻是**你正改某文件、正卡在某错误**时——而此刻没人把"这个文件的设计稿/上次同样的报错排查/相关约定"推到你面前。
- 基础其实已具备:F33(文档↔代码反查)、F44(哪些文档有用)、F47(记忆)、hooks(能感知 Edit/Write 等事件,`hooks.ts` 已有 PreToolUse)。

## 目标 / 非目标

**目标**
- **活动感知**:经 hooks(编辑/报错/任务开始)或编辑器/MCP 信号,识别"当前在干什么"。
- **主动浮现**:据此推送最相关的 文档(F33 反查)/ 决策与坑(F47 记忆)/ 近期变更(F28),带相关性与出处。
- **多触点**:Claude Code hook 注入("你在改 auth.ts,相关:design/鉴权改造、debug/登录超时")、TUI 环境感知区块、(F27)Web 侧边栏。
- **安静、可控**:相关才推、可静音、可调阈值(F18),绝不打扰。

**非目标**
- 不打断流程/不刷屏(低噪音、可关)。
- 不做编辑器深度集成的全部形态(先做 hook + MCP + TUI;IDE 插件留 F50 生态)。

## 用户故事

- 作为开发者,我一打开 `auth.ts`,docky 自动提示"相关设计 + 上次同类 bug",省去回忆与搜索。
- 作为 agent,我开始处理一个文件时,自动获得该文件相关的决策/坑(F47),少踩坑。

## 交互设计

```
# Claude Code SessionStart/Edit hook 注入
docky ⟐ 你正在改 src/auth.ts —
  设计:design/鉴权改造.md   上次同类:debug/登录超时.md
  ⚠ 约定:鉴权改动需同步更新 SDK 版本(记忆 F47)
```

## 技术落点

- `src/ambient.ts`:输入"活动信号"(文件/错误/任务)→ 输出相关知识(F33 反查 + F47 召回 + F28 变更),按相关性排序、去噪。
- 触点:扩展 `hooks.ts`(Edit/Write 后注入相关知识)、MCP `relevant_for(path|context)`、TUI 区块。
- 阈值/静音经 F18;出处回链复用 F01。

## 验收标准

- [ ] 能据当前活动(文件/错误/任务)主动浮现相关文档/记忆/变更,带出处。
- [ ] 至少覆盖 Claude Code hook 注入 + MCP `relevant_for` + TUI 区块。
- [ ] 低噪音:相关性阈值可调、可静音(F18);默认不打扰。
- [ ] 作用域隔离不变;`src/ambient.ts` 相关性逻辑有单测。

## 衡量指标

- 主动推荐被点击/采用的比例(相关性达标)。
- "改某文件前先翻文档"的手动搜索减少。

## 风险与依赖

- 噪音是最大风险:宁可少推、要准;阈值 + 静音 + 反馈学习(F44)。
- 依赖 F33(代码↔文档)、F47(记忆)、F28(变更)、hooks/MCP(感知与注入)、F18(阈值)。

## 与其他提案的关系(迭代递进)

- 把 **F33/F44/F47/F28** 组合成"**在对的时刻主动推送**"的环境智能。
- 与 **F46/F47** 构成知识三态:F46 你问、F47 agent 自动记、**F48 主动提醒**。
