# F49 · Agent 会话录制 · 回放 · 自动沉淀

> 一句话:把一次完整的 agent 工作过程(改了什么、为什么、踩了什么坑)**录进 docky**,可检索、可回放,并**自动蒸馏**成一篇干净的过程文档——让团队的 agent 工作沉淀为可复用的资产,而不是会话一关就蒸发。

## 战略定位(为什么这是旗舰级跃迁)

Claude Code 的会话价值巨大,但**关掉就没了**。docky 天生是"过程文档的家"——若能**自动捕获并沉淀**每次 agent 运行,团队的集体 agent 工作就变成**持续累积的机构记忆**:别人能搜到、能回放、能复用。这是把 docky 从"手动归档"推向"自动沉淀知识引擎"的关键一跃。

## 背景与痛点

- docky 的立意是"agent 把过程文档落库",但今天**靠 agent/人主动写**(`write_doc`、`add`、F06 `/new`);大量会话里的决策与踩坑**根本没被记下来**,会话结束即丢失。
- hooks 目前只有 `SessionStart` + `PreToolUse`(`src/hooks.ts:78-79`),**没有会话结束的捕获钩子**,也没有"把这次干了啥自动总结成文档"的能力。
- F22(审阅)、F20(去重)其实已备好"接住自动产出"的下游,只缺上游的自动捕获。

## 目标 / 非目标

**目标**
- **录制**:经新增 hook(会话结束/停止)+ MCP,捕获一次运行的关键轨迹(改动文件、关键决策、报错与解决),作用域内存储。
- **自动沉淀**:把轨迹**蒸馏**成一篇结构化过程文档(debug/plan,套 F06 模板,用 F46 的模型做摘要),默认 `source:agent, review:pending`(F22)。
- **检索与回放**:沉淀文档可被 F13/F26/F46 检索;原始轨迹可按时间线"回放"查看(复用 F08/F16)。
- **隐私可控**:本地、可开关、可脱敏(不录密钥/敏感内容)。

**非目标**
- 不强制录制(opt-in);不外传(本地)。
- 不取代人工撰写的精炼设计稿(自动沉淀是初稿,经 F22 审阅成型)。

## 用户故事

- 作为团队,昨天 agent 修了个棘手 bug,今天我搜得到它自动沉淀的排查文档,还能回放它当时的关键步骤。
- 作为维护者,我在收件箱(F22)把这篇自动沉淀的初稿润色后通过。

## 交互设计

```
# 会话结束 hook 自动触发
docky ⟐ 已沉淀本次会话 → debug/登录超时排查(草稿·待审)
  改动:src/auth.ts, src/session.ts   决策:改用 JWT   坑:回调需幂等
$ docky replay <session-id>     # 时间线回放关键步骤
```

## 技术落点

- 扩展 `src/hooks.ts`:新增会话结束/停止钩子 + 安装项(`hookEntries`),捕获轨迹。
- `src/capture.ts`:轨迹存储(作用域内,F37 原子)、蒸馏(F46 模型,套 F06 模板)、`source/review`(F22)。
- 回放:时间线视图(复用 F16/F08);沉淀文档进入正常检索(F13/F26/F46)。

## 验收标准

- [ ] 会话结束可捕获关键轨迹并自动沉淀为结构化文档(默认待审 F22)。
- [ ] 沉淀文档可被检索/问答(F13/F26/F46);轨迹可回放。
- [ ] opt-in、本地、可脱敏;无模型时退化为"轨迹要点列表"。
- [ ] 作用域隔离不变;捕获/蒸馏有单测(模型可 mock)。

## 衡量指标

- 自动沉淀文档占新增过程文档的比例(捕获覆盖率)。
- 沉淀初稿经审阅通过率;历史会话被检索/回放的次数。

## 风险与依赖

- 隐私/脱敏是底线:默认 opt-in、本地、过滤敏感内容。
- 依赖新增 hook、F06(模板)、F46(蒸馏模型)、F20(去重)、F22(审阅)、F08/F16(回放)、F37(原子存储)。

## 与其他提案的关系(迭代递进)

- 补上 docky 立意的"**自动捕获**"上游:F49 录入 → F20 去重 → F22 审阅 → 进入检索/记忆(F26/F47)。
- 与 **F47** 闭环:会话沉淀出的决策/坑可升格为 F47 的结构化记忆。
