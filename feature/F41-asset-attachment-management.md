# F41 · 附件与图片资源管理

> 一句话:让文档能**带上图片/附件**并被 docky 统一管理——随文档迁移、随导出打包、作用域内安全——而不是只能存裸 `.md`、图片路径一搬就断。

## 背景与痛点

docky 只认 `.md`,**附件无处安放**:

- `listDocs` 只收 `.md` 文件(`src/core.ts`);vault 结构是 `projects/<项目>/<类型>/*.md`,**没有任何非 md 资源(截图、架构图)的位置**。
- design 文档常引用图片,但图片要么散在业务仓库(docky 与业务 git 解耦,一搬就断链),要么根本没法跟着文档走。
- F17 导出 / F27 Web 无法把图片一起打包;F19 巡检也发现不了"图片丢了"。

## 目标 / 非目标

**目标**
- **附件目录**:作用域内 `projects/<项目>/_assets/`(或按文档分子目录),`docky attach <rel> <文件>` 复制资源进库并在文档插入/改写**相对链接**。
- **随文档走**:`mv`/`rm` 文档时同步迁移/清理其附件(GC),链接不断。
- **随导出走**:F17 导出 / F27 Web **打包并正确引用**附件。
- **被巡检**:F19 检测缺失附件(链接指向不存在)与孤立附件(无人引用)。

**非目标**
- 不做图床/云上传(本地附件即可)。
- 不在终端渲染图片(终端显示路径/占位;真渲染交给 F17/F27)。

## 用户故事

- 作为开发者,`docky attach design/架构.md ./架构图.png`,图片进库、文档自动插入链接,日后导出仍能看到图。
- 作为维护者,F19 告诉我哪篇文档的图丢了、哪些图没人用。

## 交互设计

```
$ docky attach design/架构.md ./diagram.png
✓ 已附加 _assets/架构-diagram.png,并在文档插入 ![](../_assets/架构-diagram.png)
$ docky doctor      # (F19)
⚠ design/旧设计.md  引用的 _assets/old.png 不存在
```

## 技术落点

- 约定 `_assets/`(以 `_`/`.` 前缀,排除出 `listDocs`/INDEX);`safePath` 守边界。
- `src/assets.ts`:`attach`(复制+改链)、`mv`/`rm` 联动迁移/GC、引用扫描(供 F19、F17/F27)。
- `src/cli.ts`/`commands.ts`:`attach` 命令;F17/F27 打包附件;F19 增检查项。

## 验收标准

- [ ] `docky attach` 把资源复制进作用域附件区并改写文档链接。
- [ ] 文档 `mv`/`rm` 时附件同步迁移/清理,链接不断。
- [ ] F17 导出 / F27 Web 正确打包并引用附件。
- [ ] F19 检出缺失/孤立附件;附件不被当作文档列出。
- [ ] 作用域隔离不变;`src/assets.ts` 有单测。

## 衡量指标

- 带附件且导出后图片完好的文档比例。
- 因路径搬迁导致的断图减少。

## 风险与依赖

- 附件可能较大:提示体积、可配忽略;GC 需谨慎(仅清无引用者)。
- 与 F17/F27(打包)、F19(检查)、F10(rm 联动)、F08(提交)协同。

## 与其他提案的关系(迭代递进)

- 把 docky 从"纯文本库"扩展到"**图文并茂**",补齐 design 类文档的内容完整性。
- 被 **F17/F27** 打包、被 **F19** 巡检、随 **F10/F08** 安全增删与留痕。
