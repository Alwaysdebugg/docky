# F26 · 语义检索(embedding + 混合检索)

> 一句话:给 docky 装上**语义检索**——按意思而非字面找文档,并与 F13 的关键词检索**混合**排序,让人和 agent 都能用"大概是讲这个的"找到对的文档。

## 背景与痛点

这是被反复推迟、却最该补的能力:

- F13 升级了关键词检索、F07 做了上下文包,但**两者都明确把语义检索列为非目标**(F07:"语义/embedding 检索留待后续轮次";F13 同);README 路线图也写着 **「语义检索(embedding)」** 未完成。
- 现状是纯字面匹配(`searchDocs` 子串,`core.ts`):搜"登录"找不到只写了"鉴权 / auth / 会话"的文档;搜"崩溃"漏掉"crash / panic"。对一个要喂 agent 的库,**召回不全**是硬伤。

## 目标 / 非目标

**目标**
- **文档向量化**:分块嵌入,索引存于作用域内(如 `projects/<项目>/.docky-index/`),随写入/F08 提交**增量更新**。
- **语义检索 + 混合排序**:`docky search --semantic`,默认走**混合**(F13 关键词 + 向量,RRF 融合),兼顾精确与语义召回。
- **赋能 F07**:`get_context` 的召回改用混合检索,相关性更高。
- **可插拔嵌入源**:本地模型(如 transformers.js)或 API(经 F18 配置);**无嵌入源时自动退回 F13**,绝不报错。

**非目标**
- 不强制联网/外部 API(本地优先,API 可选)。
- 不替代关键词检索(精确匹配仍走 F13;语义是补充)。

## 用户故事

- 作为开发者,我搜"为什么会话会丢",即使文档里写的是"session 过期",也能被找到。
- 作为 agent,我的 `get_context` 召回了语义相关但用词不同的设计稿,少漏关键上下文。

## 交互设计

```
$ docky search "会话为什么会丢" --semantic
design/鉴权改造.md      ~0.88  (语义)   …session 过期策略…
debug/登录排查.md       ~0.71  (混合)   …token 失效导致 302…
(默认混合;--semantic 偏语义,--exact 退回 F13)
```

## 技术落点

- `src/embed.ts`:可插拔嵌入器接口(local / api / none);维度与模型经 F18 配置。
- `src/vindex.ts`:构建/查询向量索引(余弦),增量随写入或 F08 提交更新;索引目录以 `.` 前缀,排除出 `listDocs`/INDEX(同 F10 trash 处理)。
- 融合:与 `searchDocs`(F13)做 RRF;`buildContext`(F07)改调混合检索。
- 缺嵌入源时全链路降级为 F13。

## 验收标准

- [ ] 文档可嵌入并建立作用域内向量索引,增量更新。
- [ ] `search` 默认混合;`--semantic`/`--exact` 可切;结果标注来源(语义/关键词/混合)。
- [ ] `get_context`(F07)召回改用混合检索。
- [ ] 无嵌入源时优雅退回 F13,不报错。
- [ ] 索引不被当作文档;越界不可见;`embed`/`vindex`/融合有单测。

## 衡量指标

- 同一信息需求下的召回率(语义命中此前漏掉的文档数)。
- agent get_context 的"相关文档命中率"提升。

## 风险与依赖

- 本地嵌入模型体积/首次下载成本;给出"无模型即降级"的明确路径。
- 索引与文档一致性:写入/删除需同步维护(挂到 F08 提交事件最稳)。

## 与其他提案的关系(迭代递进)

- **兑现 F07/F13 共同推迟的语义目标**、落地 README 路线图项;与 F13 **混合**而非取代。
- 直接增强 **F07** 的 agent 上下文召回;为 **F27 web**、**F24 智能文件夹** 提供更强的检索内核。
