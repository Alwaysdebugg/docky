# F46 · Ask Docky — 知识库自然语言问答

> 一句话:直接用自然语言**问**整个知识库——"我们当时为什么选 JWT?"——docky 检索 + 综合,给出**带引用**的答案。把文档库从"能搜到"升级为"能回答"。

## 战略定位(为什么这是旗舰级跃迁)

今天 docky 帮你**找到**文档(F01/F13/F26)、给 agent **喂**上下文(F07)。但它仍是个"被动书架"——答案在你脑子里拼。要对标 Claude Code,docky 需要一个**对话式问答面**:你问,它答,并标明出处。这一步把 docky 从"文档管理器"变成"团队的知识神谕(oracle)",是面向人的旗舰交互。

## 背景与痛点

- F26(语义检索)能返回**相关文档**、F07(`get_context`)给 agent 拼**上下文包**,但**没有一个把答案直接综合出来给人**的入口。
- 用户要回答"这个模块当初的设计取舍是什么",得自己搜→逐篇读→脑内汇总,跨 design/debug/plan 多篇尤其累。

## 目标 / 非目标

**目标**
- `docky ask "<问题>"` / TUI `/ask` / MCP `ask` 工具:**检索(F26 混合)→ 综合 → 带引用作答**(每条结论标注来源文档:行,可 Enter 打开,复用 F01)。
- **作用域安全**:仅在当前项目(或 F15 授权域)内检索作答,绝不泄漏他项目。
- **模型可配**(F18):默认 Claude(Anthropic 系);**无模型时优雅降级**为"列出最相关段落"(即 F26 结果),绝不假装作答。
- 追问连续对话(保留检索上下文)。

**非目标**
- 不做模型微调/训练(检索增强 + 现成模型)。
- 不臆造:无依据时明说"库中未找到",并给出最接近的来源。

## 用户故事

- 作为新接手的人,我问"退款回调失败一般是什么原因?",docky 综合历史 debug/design 给出带引用的答案。
- 作为 agent,我经 MCP `ask` 直接拿到带出处的结论,而非自己读一堆文档。

## 交互设计

```
$ docky ask "我们为什么放弃 session、改用 JWT?"
答:主要因横向扩展下的会话粘性问题与跨服务鉴权成本。
  依据:
  [1] design/鉴权改造.md:42  「session 粘性导致扩容困难…」
  [2] debug/登录排查.md:13    「会话丢失 → 302…」
(输入序号打开来源 · 继续追问 · q 退出)
```

## 技术落点

- `src/ask.ts`:检索(复用 F26 混合 / F07 `buildContext`)→ 组装带引用的 prompt → 调用可配模型 → 解析"结论+引用"。
- 引用回链复用 F01 `pageDoc(rel, line)`;`docky ask` / `/ask` / MCP `ask`。
- 模型经 F18 配置;无模型回退到 F26 段落列表。

## 验收标准

- [ ] `docky ask`/`/ask`/MCP `ask` 返回综合答案 + 可点击引用(文档:行)。
- [ ] 仅在作用域/授权域内检索作答;越界不可见。
- [ ] 无依据时明确说明,不臆造;无模型时降级为段落列表。
- [ ] 支持连续追问;模型经 F18 可配。
- [ ] 检索→引用解析有单测(模型层可 mock)。

## 衡量指标

- "问题 → 满意答案"的完成率;问答替代"手动搜+读"的比例。
- 答案引用的有效点击率(出处可信)。

## 风险与依赖

- 防臆造:强制"先有引用再有结论",无据则拒答。
- 依赖 F26(检索)/F07(上下文)/F18(模型)/F01(引用回链)。

## 与其他提案的关系(迭代递进)

- 在 **F26/F07** 的检索之上加"**综合作答**"层,是面向人的旗舰交互。
- 与 **F47 记忆层**互补:F46 回答"库里怎么说",F47 让 agent"自动记得";同一检索内核(F26)支撑二者。
