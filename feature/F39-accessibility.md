# F39 · 无障碍与可访问性

> 一句话:让 docky 对**色盲/低视力用户、不支持颜色的终端、读屏软件**都友好——信息不只靠颜色传达,并支持 `NO_COLOR`、高对比与纯文本模式。

## 背景与痛点

TUI **重度依赖颜色**且无任何无障碍开关:

- 大量信息**只用颜色**区分:DOCKY 渐变字标(`GRADIENT`)、级别配色(`colorOf`:in/info/err/ok)、F03 状态徽标着色、选中态 `inverse`(`src/tui.tsx`)。
- **不识别 `NO_COLOR`**、没有高对比/色盲安全配色、没有纯文本(读屏友好)模式;渐变在某些终端/低视力下几乎不可读。
- 对依赖读屏或无法分辨颜色的用户,**部分状态根本无法感知**(如仅靠红/绿区分成败)。

## 目标 / 非目标

**目标**
- **尊重 `NO_COLOR` / `--no-color`**,提供高对比与**色盲安全**配色预设。
- **信息不只靠颜色**:状态/级别同时带**符号 + 文字**(如 `✗ error`、`[archived]`、`⚠ stale`),去色后仍可读。
- **纯文本/读屏模式**:稳定、线性、少装饰的输出(关渐变与动态重绘)。
- 预设经 F18/F16 主题体系选择(新增 a11y 预设)。

**非目标**
- 不牺牲默认观感(a11y 为可选模式/自动按 `NO_COLOR`)。
- 不做完整 WCAG 认证(聚焦终端可达性要点)。

## 用户故事

- 作为色盲用户,我靠符号 + 文字也能分清成功/失败/陈旧,不只看红绿。
- 作为读屏用户,我用纯文本模式,输出线性可读,无花哨重绘干扰。

## 交互设计

```
$ NO_COLOR=1 docky list
[active]  design/架构.md   #登录
[stale!]  debug/旧排查.md            ← 去色后靠 [..]/! 仍可辨
$ docky --theme high-contrast ...
```

## 技术落点

- 颜色统一过一层 `palette`(扩展 F16/F18 主题):支持 `default / high-contrast / colorblind / mono`;读 `NO_COLOR`/`--no-color`/能力探测。
- 把"仅颜色"的信号补上符号 + 文字(改 `colorOf` 调用点与 F03 徽标渲染)。
- 纯文本模式:关 `GRADIENT` 与强制重绘,输出线性化。

## 验收标准

- [ ] `NO_COLOR`/`--no-color` 被尊重;去色后所有关键信息仍可辨(符号+文字)。
- [ ] 提供高对比与色盲安全配色预设(经主题选择)。
- [ ] 纯文本/读屏模式输出线性、无依赖颜色的语义丢失。
- [ ] 默认观感不变;a11y 模式可自动(NO_COLOR)或手动启用。
- [ ] 调色板/降级渲染有单测(含 NO_COLOR 快照)。

## 衡量指标

- 去色快照中"语义未丢失"的检查项通过率。
- 来自无障碍/终端兼容的可用性反馈改善。

## 风险与依赖

- 给所有"仅颜色"处补符号需全面排查,避免遗漏。
- 扩展自 F16(渲染主题)/F18(配置);与 F38 同为"更多人用得了"的内功。

## 与其他提案的关系(迭代递进)

- 把 **F16 的渲染主题**从"好看"扩展到"可达",并由 **F18** 统一选择。
- 与 **F38**(可发现性)、**F40**(多语言)共同构成"人人可用"的体验底座。
